# TARGET frontier JV → KiriScoreモデル 運用ガイド

無料期間1ヶ月の使い方を「最大効率」で設計したガイド。
**最優先タスクは、無料期間中に過去10年分のデータをCSVで手元に確保すること。**
一度エクスポートしたCSVは解約後も学習に使い続けられる（利用規約の範囲でご自身の分析用に）。

## 全体像

```
【月1回・ローカルPC】
TARGET → 過去レースCSV出力 → target_import.py → train_model.py
                                                      ↓
                                          model_weights.json を
                                          frontend/src/lib/ へ上書き → デプロイ

【毎週末・レース当日】
TARGET → 当日出馬表CSV出力(直前オッズ入り)
       → サイトの「モデル予測」ページにドロップ
       → 🔥フラグの馬だけ購入(表示された推奨額の半額以下から開始)
```

## STEP 1: TARGET初期設定（初回のみ・所要1〜3時間）

1. JRA-VAN Data Labの利用登録とTARGET frontier JVのインストールを完了させる
2. TARGET初回起動時の「データ登録(セットアップ)」で **過去データの取得年数を最大**に設定
   （ダウンロードに数時間かかるが、これが資産になる。最低でも2016年以降を推奨）
3. 週次で「差分データ取得」を実行する習慣をつける（数分で完了）

## STEP 2: 学習用CSVの出力（月1回）

1. TARGETのレース検索（拡張検索）で期間を指定（例: 2018/01/01〜先週）
   - 対象: 中央・平地のみ（障害は取込み時に自動除外されるが外せるなら外す）
2. 検索結果一覧 → CSV出力（出力項目設定で以下の列を必ず含める）

   **必須列**: 日付 / 場所 / R / 距離 / 芝ダ / 頭数 / 馬番 / 馬名 / 性齢 /
   騎手 / 斤量 / 馬体重 / 増減 / 単勝オッズ(確定) / 着順

   **推奨列**（精度向上）: 前走着順 / 前走頭数 / 前走日付 / 前走距離

   ※ 列名がTARGETのバージョンで多少違っても、target_import.pyが
     エイリアス表で吸収します。取り込めない列があれば警告が出るので、
     その列名を target_import.py の ALIASES に追記してください。

3. 変換と学習:
```powershell
python target_import.py TARGET出力.csv --out train_data.csv
python train_model.py train_data.csv
```

4. 出力された model_weights.json を確認:
   - **検証logLossがモデル<市場なら合格** → サイトに組込む
   - 市場に届かない場合もEV閾値を1.3以上に上げれば実験運用は可能だが、
     期待回収率は100%未満とみなすこと

5. サイトへの組込み:
```powershell
copy model_weights.json ..\frontend\src\lib\model_weights.json
git add ..\frontend\src\lib\model_weights.json
git commit -m "モデル再学習"
git push
```

## STEP 3: レース当日の運用（週末）

1. 発走30〜10分前にTARGETで当日レースをCSV出力
   - 列構成は学習用と同じ（着順は不要）
   - **オッズ列は必ず「現在オッズ」で出力**（古いオッズはEV計算を狂わせる）
2. サイトの「モデル予測」ページを開き、CSVをドラッグ&ドロップ
3. 🔥フラグ（EV≥閾値）の馬の単勝のみ購入
   - 初月は表示推奨額の**半額以下**で（確定オッズ学習バイアスの検証期間）
   - 全購入を記録し、月末に実回収率とバックテストの乖離を確認

## 判断基準の優先順位

1. 検証logLoss: モデル < 市場 が全ての前提
2. EV閾値別回収率: ベット数500以上の行のみ信用
3. 実運用記録との乖離: バックテスト比-5〜10%以内なら正常

## してはいけないこと

- 学習期間と検証期間を混ぜる（train_model.pyは自動で分割するが、
  同じデータで何度も閾値をいじって「良い結果」を探すのも同種の過剰適合）
- 50ベット程度の好成績で賭け金を増やす（最低500ベット、理想900ベット）
- logLossが市場に勝てていないのにEV閾値1.0近辺で大量購入する
- 単勝で伸び悩んだら: 同じ勝率モデルから馬連・3連複の確率を組み立てる
  拡張が次の一手（Harville式）。控除率は上がるが市場の歪みも大きい。
