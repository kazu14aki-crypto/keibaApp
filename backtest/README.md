# KiriScore 期待値検証ツールキット

「当てる」から「儲かる期待値だけを買う」への転換に必要な検証基盤。

## 全体フロー

```
① データ蓄積 (アプリで採点・オッズ・結果を記録)
        │  export_from_app.py
        ▼
② CSVエクスポート (kiriscore_data.csv)
        │  backtest.py
        ▼
③ 較正 + 検証 (β・ブレンドw・logLoss・回収率)
        │  較正値をUIの期待値分析パネルに反映
        ▼
④ 実運用 (EV閾値を超えた馬だけ購入、1/4ケリーで資金配分)
```

## ファイル一覧

| ファイル | 役割 |
|---|---|
| `backtest.py` | 較正・ウォークフォワード検証・戦略シミュレーション |
| `export_from_app.py` | アプリのAPIからバックテスト用CSVを生成 |
| `netkeiba_scraper.py` | 過去の確定オッズ・着順の収集（市場ベンチマーク用、ローカル実行、規約要確認） |

## 最初の一歩

```powershell
# 動作確認（合成データ）
python backtest.py --demo

# 実データが30レース以上貯まったら
python export_from_app.py --url https://keibaapp-wy1f.onrender.com --password xxxx --out kiriscore_data.csv
python backtest.py kiriscore_data.csv

# 新しく記録したデータではこちらを使用（オッズ取得時刻のない旧レースを除外）
python backtest.py kiriscore_data.csv --strict-odds
```

## 判定基準（この順で確認する）

1. **ブレンドlogLoss < 市場logLoss か？** — Noなら回収率100%超えは原理的に不可能。
   モデル改善（ファクターの見直し、フェーズ4のロジスティック回帰化）に戻る。
2. **較正曲線が対角線に乗っているか？** — 予測10%の馬が実際に10%勝っているか。
   乖離していればβを再較正。
3. **事前固定戦略の回収率と95%区間** — `backtest.py` は学習期間内の別検証区間で
   購入閾値を固定し、最後のテスト期間には触れずに評価する。テスト表の最高ROIを
   後から採用しない。ベット数500以上、かつ95%区間の下限も確認する。
4. 実運用の期待回収率 = バックテスト値 − 5〜10%（確定オッズバイアス）。

## データ蓄積を最速化する運用（フェーズ2の時短）

- 週末ごとに「全重賞 + 気になる特別戦」を機械的に取り込む（1レース3分）
  - 土曜朝: JRA URLで取込み → 自動計算ボタン
  - 発走10分前: 単勝オッズを期待値分析パネルに入力
- 月曜: 結果着順を入力
- 週30レース × 2ヶ月 ≒ 250レース。100レース到達時点で初回較正。
- **本格的にやるなら JRA-VAN Data Lab（月額約2,090円）+ TARGET frontier JV。**
  過去30年の全データが1日で手に入り、スクレイピング不要になる。
  株で言えば「有料データベンダーの正規データを使う」のと同じで、
  この金額で得られる時間短縮を考えれば圧倒的に安い。

## オッズ時点の監査

オッズ入力時にサーバーがUTCの取得時刻を保存します。既存のDBは次回起動時に
`odds_captured_at` 列を自動追加します。旧データには時刻がないため、厳密な評価は
`--strict-odds` を付けて実行してください。取得時刻が残っていても、確定後に手入力した
値を区別できるわけではないため、発走前に記録する運用を固定してください。

## 統計的な心得

- 回収率110%を偶然と区別するには約900ベット必要（単勝リターンのσ≒3×賭け金）。
- 50ベットの回収率150%より、800ベットの回収率105%のほうが遥かに価値がある。
- モデルが市場に勝てるのは通常、市場の盲点（少頭数・ローカル・ハンデ戦・
  新馬戦など情報の薄いレース）に限られる。全レースで勝とうとしないこと。
